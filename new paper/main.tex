\begin{abstract}
We ask whether a general-purpose coding agent, given no hint about where a
program spends its time, can find and fix a real performance bottleneck in a
mature C codebase. Two agents --- Claude Code and Codex --- were each given an
identical checkout of GraphViz pinned to the same commit and the same
open-ended instruction: make the \texttt{dot} layout program faster without
changing its output. Neither was told which function, file, or phase to target,
and neither had access to the evaluation harness or the benchmark graphs.
Both agents independently identified crossing minimization as the dominant
cost, and both produced output-preserving speedups under independent
measurement: $1.47\times$ and $1.16\times$ end-to-end on a 5{,}000-node graph,
against an empirically measured noise floor of $8.4\%$. Neither agent used
parallelism; both pursued serial algorithmic and data-layout changes. On a
10{,}000-node graph the two diverge --- one agent improves to $1.57\times$
while the other stays flat at $1.15\times$ --- and the phase-level data
explains why: the workload's dominant phase shifts from crossing minimization
to coordinate assignment as the graph grows, and only one agent had touched
the latter. We report what we measured, state the ceiling that bounds it, and
name what we did not verify.
\end{abstract}
