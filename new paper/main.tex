\begin{abstract}
Can a coding agent find and fix a real performance bottleneck on its own, with
no hint about where the program spends its time? We gave two agents --- Claude
Code and Codex --- the same untouched copy of GraphViz and the same instruction:
make the \texttt{dot} layout program faster without changing what it draws.
Neither was told which function or phase to look at, and neither could see the
benchmark we would judge them on.

Both found the same hot spot: crossing minimization, one of the five phases
\texttt{dot} runs. They differ in how far they went. Claude improved three
phases and made layout $1.33\times$ to $1.84\times$ faster. Codex improved one
phase and ranged from $1.29\times$ faster down to no measurable change at all.

That last result is the interesting one. Codex's optimization works --- it makes
that phase $1.31\times$ faster --- but on one of our graphs that phase is only
$11.5\%$ of the work, so the gain vanishes end to end. How much a phase is worth
depends on the shape of the graph, not its size: crossing minimization is
$11.5\%$ of layout time on one shape and $64\%$ on another with the same number
of nodes. We measured how far apart two runs of the \emph{unmodified} program
land, and report only differences larger than that.
\end{abstract}
